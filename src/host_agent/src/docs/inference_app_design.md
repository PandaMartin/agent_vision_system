## 三、总体架构与数据流

```
gui任务(推理应用UI)              app_task(推理循环)                 vid任务(30fps)
─────────────────              ──────────────────                ─────────────────
 模型键  → MODEL_SELECT    →   激活模型(读SD, FatFs纪律)
 图片键  → 面板切图片浏览   →   PHOTO_LOAD(path) 读BMP发布
 推理键  → PHOTO_INFER     →   对当前图单次前向+后处理 → 发布
 开始键  → RUN_SET 0/1     →   循环{ 抓帧(2.7MB拷贝)
                                    nn_forward_frame(按档案前向)
                                    nn_post_classify/detect(解码+NMS)
                                    bridge发布: Top-K/摘要/耗时/检测框 }
                                   加速模式: 推理完把该帧标注后
                                    经 vidwin_show_annotated 上屏
                                                                  常规模式: 每帧降采样blit后,
                                                                  平滑插值最新检测框+标签,
                                                                  重画进LCD视频洞
 refresh(150ms)读快照 ←────── bridge(唯一跨任务数据桥) ──────→ (可另往HDMI帧环描框)
```

- **重活全在 app_task**（FatFs 唯一使用者纪律）；推理循环每轮之间非阻塞检查命令队列，停止/切模型最长等一帧推理（几百 ms）即响应
- 检测框数据随推理速率(~5fps)更新，画面以 30fps 刷新，两者解耦

## 四、模型管理

**SD 卡约定**（model_mgr 已实现，零代码）：`/models/<文件夹>/` 内放：

```
model.cfg        档案: name/input_size/mean/norm/post(classify|detect)/
                 score_th/nms_iou_th/topk 等(key=value)
model.param.bin  ncnn 网络结构(ncnn2mem 产物)
model.bin        ncnn 权重
labels.txt       类别名每行一个, 行号=类别号(检测0号=background)
```

- **加新模型 = 拷文件夹，不改代码**；模型面板带"刷新"键重扫 SD（换卡免重启）
- `post=classify` → Top-K 路径；`post=detect` → SSD 解码+NMS 路径，UI 自动跟随
- labels.txt 需用**英文类别名**（VOC/COCO 标准惯例；视频洞内位图字体只支持 ASCII）

## 五、摄像头实时推理模式

### 5.1 推理循环（app_task）

抓帧（帧边界同步 + 2.7MB 整帧拷贝，静态缓冲复用不反复 malloc）→ 按档案前向 → 后处理 → 发布。
耗时逐次发布（bridge 已有环/均值/峰值字段），状态行显示单帧耗时与实测 fps。

### 5.2 检测框叠加机制（LCD 视频洞直写）

视频画面是 vid 任务绕过 LVGL 直写帧缓冲的"洞"（640x360，内容区水平居中），框必须同样直写：

- **常规预览**：vid 任务每帧 blit 完成后，把平滑后的检测框（相机 1280x720 坐标 ×0.5）重画进洞。每帧重画 → 零闪烁
- **样式**：角括号式画框（只画四角，不遮目标本体）+ 2px 类别色线 + 1px 深色外沿（复杂背景不迷失）+ 框顶标签条（底色条与框同色，内写 `person 87%`；贴近画面顶部的框标签自动翻到框下方）
- **配色**：按类别号从固定鲜艳色板（红/绿/青/黄/品红/橙…）循环取色，同类同色
- **标签字体**：新写 `ovl_draw` 模块——8x8 ASCII 位图字体（公有领域）放大 2 倍（16x16），直接往 RGB888 缓冲渲染；LCD 洞与 HDMI 帧环共用

### 5.3 低帧率视觉体验设计（3~10fps 的核心对策）

| 硬伤 | 对策 |
|---|---|
| 框每 200ms 瞬移跳变（画面 30fps 流畅，反差刺眼） | 框与推理解耦，30fps 重画 + **指数平滑插值**：新真值与当前框做 **IoU>0.3 贪心配对**，配对成功每帧向真值靠近 35%（α≈0.35，约 3~4 帧滑到新位置） |
| 目标消失/出现突兀 | **渐入渐出**：消失的框保留 ~4 视频帧宽限期（线宽递减收细）再撤；新框从 80% 尺寸放大就位 |
| 框线在复杂背景看不清 | 角括号 + 深色外沿 + 标签底色条（见 5.2） |

**诚实的局限**（设计上接受）：

- 框天然滞后目标约 0.2~0.3s（推理延迟+平滑时间）。慢速/静态目标体验好；快速运动目标框会拖尾
- 云台快速转动时所有目标都在"快速运动"，框整体滞后——5fps 推理的物理极限，停稳后立刻跟上
- 可选对策（默认关，留调优常量）：按最近两次结果做线性外推，提前预判一个推理周期

### 5.4 预览开关与加速模式

预览占约 10~15% CPU + ~150MB/s DDR 带宽（与推理争总线）。开关语义：

```
预览 开(默认): vid任务 30fps 降采样直播 + 插值平滑框
预览 关(加速): vid任务完全停笔(零CPU零带宽);
               app_task 每完成一次推理, 把"刚推理的那一帧"(本来就在
               DDR的静态拷贝)降采样 + 画上该帧自己的检测框, blit进洞
               → 洞变成 3~8fps 的"标注结果回放"
```

- 回放模式**框与画面完美对位**（就是网络"亲眼看到"的那帧），无滞后问题，也方便对照调试模型
- 每周期多一次 640x360 降采样（约 2~4ms），相对 200ms 推理可忽略
- 预计提速 10~30%（界面显示前后实测 fps 对比）；追求极限速度时 HDMI 也应关闭（占带宽更大）
- 随时切回直播（云台瞄准用直播，纯跑分用回放）

### 5.5 HDMI 输出（三态按钮）

HDMI 从摄像头帧环直接读出。按钮循环三态：

```
HDMI 关  →  HDMI 开(无框, 干净画面)  →  HDMI 开(带框)  →  回到关
```

**带框档的观感与 LCD 一致丝滑**：平滑引擎（IoU 配对+插值+渐隐）在 vid 任务里只有一份，
每个帧节拍（~30fps）同时服务两个出口——LCD 洞画平滑后的框，HDMI 往"刚完成的帧环帧"
画**同一组平滑坐标**的框再交由 VDMA 读出显示。因此 HDMI 上的框同样是 30fps 连续滑动
跟随，不是每 200ms 跳一格。

与 LCD 的三处微小差异（均不影响观感，如实说明）：

| 差异 | 原因 | 处理 |
|---|---|---|
| 多 1~2 帧显示延迟(~33-66ms) | 帧环帧描完框后要等 MM2S 读到它才上屏 | 相对推理本身的 0.2-0.3s 滞后不可感知 |
| 框线相对更细 | HDMI 是全幅 1280x720, 2px 线占比小于 LCD 洞(640x360) | HDMI 描 3px 线, 视觉权重与 LCD 对齐 |
| 拍照污染 | 框烧进帧环像素 | 需要干净照片就停在无框档(三态的意义) |

## 六、SD 图片推理模式

### 6.1 交互流程（4 面板之一/之二）

```
主面板(摄像头模式)                        图片浏览面板              图片查看面板
┌──────────────────┐    点[图片]   ┌──────────────┐   点行   ┌──────────────────┐
│  摄像头画面+框     │  ─────────→  │ IMG_0001.bmp │  ─────→ │ 整幅图片(LVGL显示) │
│                  │              │ IMG_0002.bmp │         │  + 检测框叠加      │
│ [模型][图片][预览] │   ←[返回]    │ …(复用相册行) │ ←[返回] │ [推理] [返回列表]  │
│ [HDMI][停止]      │              └──────────────┘         │ 结果行+耗时        │
└──────────────────┘                                       └──────────────────┘
```

- 进图片模式暂停摄像头预览与推理循环；返回自动恢复（链路常热，切换零成本）
- **没插摄像头的板子也能纯图片推理**（对调试模型友好）
- 单次触发：点一次`推理`跑一次，显示单帧耗时；`模型`面板跨模式共用

### 6.2 图片上的检测框（比视频模式简单）

图片走 LVGL lv_image 显示（非直写洞），框直接用 **LVGL 控件叠加**：透明底+2px 类别色描边矩形 + 标签控件，按等比缩放（CONTAIN，可精确计算）换算坐标。完美对位、无平滑需求、标签用完整字体。配色沿用同一类别色板。

### 6.3 技术要点

| 点 | 说明 |
|---|---|
| 目录 | `/photos`（与相机应用相册共用——拍照即可推理；PC 拷 BMP 进去也行） |
| 格式 | **仅 BMP**（现有解码器只支持；JPG 需引入解码器，暂不做） |
| 通道序 | BMP 像素字节序与摄像头帧相反（BGR vs RGB），图片推理路径先做一次通道交换（几 ms）再进网络 |
| 命令 | 复用 `PHOTO_LOAD`；新增 `PHOTO_INFER` |
| 分类模型 | 对图片同样适用：无框，结果行显示 Top-5 |

## 七、界面设计汇总

### 7.1 面板清单（4 个互斥面板）

1. **摄像头主面板**（默认）：视频洞 640x360 居中 + 底栏

4. **模型选择**（跨模式共用）：模型名+类型标签行，当前项高亮，[刷新][返回]

### 7.2 摄像头主面板布局（784x424 内容区）

```
┌──────────────────────────────────────────────────────────────┐
│         ┌─────────────────────────────┐                       │
│  (72,0) │      摄像头实时画面           │                       │
│         │  ┌person 92%────────┐       │  ← vid任务画的角括号框  │
│         │  └│                │ dog 76%│    和标签条(或回放帧)   │

│         └─────────────────────────────┘                       │
```

## 十、待确认决策点（附推荐，回复"确认"即全部按推荐执行）
