# 大模型协作记录

本记录汇总本项目全周期与大模型协作的真实案例：每条含**提示词要点、模型回答、纠错轨迹、可复核产物**。
总纪律（贯穿全部协作）：**引用必须可溯源、数据必须来自工程文件、模型输出的工程外名词一律回查**。
与《设计报告》§5 一致并互为索引；技能包（`skill/`）即从下列案例中提炼。

---

## 1. 文献逐条溯源工作流（→ 技能包 prompt-workflows/02）

- **提示词要点**："查阅近三年相关论文进行对比……一定要有依据"；追加强约束
  "验证一下是否真实存在，给出地址，否则就不引用"。
- **模型回答**：初轮给出 7 篇"相关文献"，其中 2 篇卷期页码存疑。
- **纠错轨迹**：模型曾未经确认先行引用两篇文献 → 人工质疑 → 逐条到出版方官网核对卷期页码与 DOI
  → 2 篇未能给出可访问地址，弃用；5 篇保留（Sensors / JESA / IEEE CEM / Forests / arXiv）。
- **固化规则**："只输出能给出可访问地址的文献"，并沉淀为技能包提示词工作流。
- **产物**：技术文档参考文献表（5 篇全部可溯源）。

## 2. 约束文件完整性审查——拆行约束陷阱（→ prompt-workflows/01）

- **提示词要点**：整理 pin.xdc 引脚分配，输出约束总表并给出每项出处行号。
- **模型回答**：首轮以正则提取得 **53 项**。
- **纠错轨迹**：人工抽查发现遗漏以**拆行形式**书写的 `set_property`（TTC0 两路舵机 PWM 约束）
  → 修正流程"正则初筛＋追加扫描拆行写法＋与工程实际端口交叉核对" → 最终确认 **55 项**。
- **产物**：技术文档表 3（55 项约束分组表）；案例固化为技能包 01-xdc-constraint-audit。

## 3. 框图识别的幻觉防护——受约束选择（→ prompt-workflows/03）

- **提示词要点**：标注 Block Design 截图中的 17 个模块名。
- **模型回答**：视觉模型在小字号徽章上两次误读——把 DVI 发送 IP 误认为采集 IP、把时钟 IP 的
  副标题 "Clocking Wizard" 误读成不存在的模块名。
- **纠错轨迹**：先从工程 `system.bd`（JSON）解析出 17 个模块名的**真值清单** → 要求模型在清单内做
  受约束选择（"是且仅是清单之一，清单外回答 none 并逐字符转录"）→ 对全部模块框做像素级字形与位置复核
  → 两种方法 17/17 对齐后才产出配图。
- **产物**：设计报告图 2（BD 模块标注图）；固化为技能包 03-diagram-recognition-guard。

## 4. 无界面环境下的 Vivado 自动化取证

- **提示词要点**：在无显示器的自动化环境里完成 Vivado 打开工程、缩放定位与截图取证。
- **关键经验**（多轮试错后形成）：
  1. 以 `vivado.jou/.log` 作为操作真值——模型自称"已打开"一律以日志为准；
  2. DPI 缩放环境下物理/逻辑坐标按 1.5 倍换算；
  3. 截图结论用相邻区域像素差分做客观验证，杜绝"看起来对了"。
- **产物**：技术文档电路章节全部配图的自主采集。

## 5. 图表生产与独立视觉验收闭环

- **流程**：报告/汇报图（系统框图、流程图、闭环图）采用"JSON 定义 → 原生可编辑 PPT 形状"生产线，
  以**独立渲染＋视觉验收＋缺陷清单回修**闭环迭代（每轮缺陷带像素级证据）。
- **纠错轨迹**：三轮迭代消除标签互压、衬垫截断虚线、图例溢出等缺陷类型。
- **产物**：数模风/经典风两套风格模板的生成脚本，换题即可复用。

## 6. 真值优先的文档生产法

- **流程**：报告与缺口清单的全部数据先行从工程文件**机器提取**（.bd 参数、pin.xdc、impl 报告、
  源码文档），模型仅负责组织成文；附录 A 即"每条表述 → 工程内来源"对照表。
- **自我纠错实例**：初稿沿用了旧记录中的自定制 TCP 协议（FWPUT2）表述；对照当前工程源码
  （`net_server.c` 头注释、`net_push.py`）发现协议已重构为标准 TFTP，遂按源码改写为两阶段演进史
  （设计报告 §4.1）——**凡与工程现状不符的记忆性表述均以源码为准**。

## 7. RTL 仿真锁定接口时序契约

- **提示词要点**：为自定义采集 IP（DVP→RGB888）编写自校验测试平台。
- **模型回答**：首轮激励在 href 抬高后隔拍送首字节。
- **纠错轨迹**：仿真自查捕获**字节整体错相**——真实 DVP 时序中数据与 href 同拍有效；修正后配对逐位正确。
- **产物**：`sim/` 一键复跑仿真（6 项自校验全部通过）；说明仿真不仅验证功能，还能反向锁定测试者
  对接口契约的理解。

## 8. 未解决项的如实记录

- 全系统偶发挂死事件（`src/host_agent/src/docs/model_platform_design.md` 及固件侧同名文档记载）：
  首查怀疑 ncnn Mat 释放，经 mallinfo 全堆遍历三分法（锁/遍历/分配）定位为**堆本身被写坏**，

## 智能体工作流设计（上位机 Agent）

除"人 ↔ 大模型"的提示词协作外，本项目把协作经验工程化为一个**可部署的上位机智能体**
（`src/host_agent/`），其工作流设计如下（全部可在工程内复核）：

### 技能文件族（agent 的"系统提示词"）

`src/host_agent/skills/host-agent/` 共 8 个 Markdown 技能文件，构成 agent 的领域知识分层：

| 文件 | 作用 |
|---|---|
| `SKILL.md` | 总纲：两条目录（上位机仓库/FPGA 工程）、一条链路（训练→导出→封包→推送→运行）、五条原则 |
| `project.md` / `fpga.md` | 仓库分工 / 板工程目录、内存划分、固件与模型如何配合 |
| `board.md` | 推板路径、长度限制、网口配置（`board_profile.json` 单一真值源） |
| `apps.md` / `ui.md` | SD 应用开发步骤 / 界面设计规范（深色卡片、字体与控件约束） |
| `shell.md` | 项目内命令的安全边界（禁破坏性命令、路径逃逸防护） |

### 工具调用层（agent 的"手"）

- `train/agent_shell.py`：项目内命令与读文件，带路径逃逸防护与危险命令黑名单；
- `train/host_skill.py`：技能检索、板卡档案、固件符号表/字库查询（`query_symbols`）；
- 训练/导出/量化审阅/封包/推送/编译应用各有专用脚本（`train/*.py`），agent 只编排不实现。

### 关键设计纪律（从失败中沉淀）

1. **不编造地址**：写应用前必须 `query_symbols` 查固件符号表，符号表缺失先 `sdapp.py export`
   ——来源：早期 agent 直接凭记忆写函数地址导致应用链接失败。
2. **量化审阅门槛**：分类模型 INT8 若比同批图 fp32 低 15 个百分点以上则下发 fp32；
   QAT 只用于分类——来源：INT8 精度回退实测。
3. **只写不读**：推送前板上"文件传输"必须开着；PC 网口按 `pc_ip_hint` 追加地址，不改动既有网络。
4. **不动 FPGA 工程**：agent 不修改固件源码/硬件描述/Vivado 工程；固件迭代走
   `adapt_firmware`（status→import→rebuild→program）固定次序。

### 与提示词协作的关系

技能文件族即"提示词工作流"的工程化形态：人机协作中验证有效的规则（溯源、真值优先、受约束选择）
被写进 agent 的技能文件，使下一个使用者不再依赖"会问的人"。技能包 `skill/` 面向人，
`src/host_agent/skills/` 面向 agent，两者同源。
