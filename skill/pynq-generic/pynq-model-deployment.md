# 通用 PYNQ 模型部署工作流（提示词工作流 + 检查单）

> **定位**：面向 PYNQ 框架的通用技能，**不与本队题目绑定**——换检测/分类任务、换 PYNQ 板卡
> （PYNQ-Z1/Z2、Zybo Z7 刷 PYNQ 镜像、Ultra96、Kria 等）均可套用。
> **验证状态（如实声明）**：本工作流的主干环节（训练 → 量化审阅 → 封包 → 推送 → 上板验证 →
> 帧率实测口径）已在本队 Zynq-7020 + ncnn + FreeRTOS 目标上完整验证并沉淀；PYNQ 特有命令
> （Overlay 加载、DPU 编译链、Jupyter 交互）按 PYNQ 官方文档整理，标 ★ 的环节未在 PYNQ
> 镜像上实测，首次使用请按检查单逐条确认。

## 适用场景

- 任意 PyTorch 训练的 CNN（分类/检测），要部署到运行 PYNQ 镜像的 Zynq/Zynq-UltraScale+ 板卡；
- 需要在"CPU 软件推理（ncnn/TFLite）"与"DPU 硬件加速（Vitis AI）"之间做路线决策；
- 需要向评委/客户给出可信的帧率与精度实测口径。

## 路线决策（第一步，先定路线再动手）

| 条件 | 建议路线 | 理由 |
|---|---|---|
| 网络结构常见（SSD/YOLO 系/分类）、量产帧率要求高 | DPU（Vitis AI）★ | B4096 算力远超 A9；但编译链长（VAI_C、量化） |
| 网络含自定义算子、或要最快出结果 | CPU 推理：ncnn（armv7l/aarch64）或 TFLite ★ | 换模型零硬件改动；A9 上小模型可实时 |
| 只是分类、模型小 | 先 CPU 路线，测完帧率再决定是否上 DPU | 避免"为加速而加速" |

本队题目最终选 CPU/ncnn 路线（换模型零固件改动），决策依据见 `report/design_report.docx` §3.1。

## 工作流（六步）

### ① 环境与板卡档案

- ★ `pip install pynq`（主机侧开发）；板卡烧 PYNQ 镜像（≥2.7，Python 3.6+/3.8 视镜像）。
- 先写**板卡档案**（本队做法：`board_profile.json` 单一真值源）：分辨率、板 IP、路径长度限制、
  模型存放路径。凡"换板要改的数字"一律进档案，不写死在代码里。
- ★ Jupyter（PYNQ 默认 `http://<板IP>:9090`）或 SSH 登板确认 Python 与内存余量。

### ② 训练与导出（主机侧）

- PyTorch 训练；导出 ONNX → ncnn（`onnx2ncnn`/`pnnx`）或 TFLite；DPU 路线导出 ONNX 待 VAI_C 编译。
- **保留 fp32 基线模型与同一批校准/测试图**——量化审阅的对照基准，帧率与精度口径同源。

### ③ 量化与审阅（关键纪律，已在本队目标验证）

- INT8 量化（ncnn：`ncnn2table`+`ncnn2int8`；DPU：Vitis AI 量化校准）。
- **审阅规则**：INT8 在同一批图上的精度比 fp32 低超过 15 个百分点 → 下发 fp32，不硬上 INT8；
  QAT 仅用于分类，且导出后不再重复本次审阅。
- 来历：本队实测 INT8 在部分检测模型上回退超阈值，该规则避免了带病上线。

### ④ 封包（模型即文件）

- 把"随模型而变的一切"（结构、权重、labels、预处理参数、解码/NMS/阈值）封成**一个自描述包/目录**，
  运行时按清单装载；换模型 = 换一个目录，不改编译产物。
- ncnn 路线可用 `ncnn2mem` 拆 param.bin/bin（本队做法）；PYNQ 上等价于"模型目录 + 一个 loader notebook"。

### ⑤ 推送与上板运行

- ★ PYNQ 上最简推送是 SCP/SFTP（`scp -r model_dir/ xilinx@<板IP>:~/jupyter_notebooks/`），
  或 U 盘直拷；比自研传输协议优先。
- ★ CPU 路线：板端 `python3 infer.py`；DPU 路线：`Overlay("dpu.bit")` → DPURunner 加载 xmodel。
- 首次运行打印：模型名、输入尺寸、单帧耗时、类别命中数——四项齐了才算"跑通"。

### ⑥ 实测口径（向评委交数）

- 帧率 = 稳态单帧耗时的倒数（预热 10 帧后测 100 帧取中位），注明：模型、输入尺寸、量化位宽、
  是否叠加前/后处理、板卡与镜像版本。**不要报"理论上多少 fps"**。
- 精度 = 与 fp32 基线在同一测试集上的对比表（本队示例见 `data/reference_results.md`）。

## 检查单（失败条件与排查）

| 症状 | 多半原因 | 排查 |
|---|---|---|
| ★ `ImportError: lib...so` on board | 镜像内缺运行库（ncnn 编译目标不一致） | 板端重编 ncnn（用镜像自带 gcc），或在镜像容器里编译 |
| ★ Overlay 加载卡死/报 bit 文件不符 | 比特流与镜像 base overlay 版本不匹配 | 用镜像自带的 dpu overlay；或按当前镜像重新生成 |
| INT8 精度骤降 | 校准集分布偏 | 换校准集重做 ③；仍超阈值按规则下发 fp32 |
| 帧率远低于预期 | 前/后处理占了大头 | 分段计时（预处理/前向/后处理），只优化最慢段 |
| 换板后路径/分辨率错 | 数字写死在代码里 | 回到 ①，把参数收回板卡档案 |

## 从本队工程迁移时替换什么

- 保留：六步流程、量化审阅规则、封包原则、实测口径；
- 替换：运行时（ncnn/FreeRTOS → PYNQ Python）、推送方式（TFTP → SCP）、板卡档案内容。
